# Harlan's Legacy — Platform

A living archive of memory. The public site is unchanged in look and feel; it
is now driven by structured data with a real admin dashboard behind it.

## Run it

No dependencies to install — Node 16+ only.

```bash
node server.js
```

- **Site**  → http://localhost:4317/
- **Admin** → http://localhost:4317/admin/
- Change the port with `PORT=8080 node server.js`

To regenerate the site from data without the server:

```bash
node build.js
```

## How it fits together

| Path | Role |
| --- | --- |
| `data/stories.json` | **Single source of truth** for every story + all metadata |
| `data/site.json` | Site config: archive total, themes, featured quote, book parts |
| `data/entities.json` | Permanent registry: the **family** (people, relationships, bios, timelines, photos) plus places / objects / events |
| `build.js` | Generator: writes story pages, the family tree + profiles, injects the homepage, mirrors `stories.js` |
| `lib/family.js` | Family Tree generator — `family.html` + one `family/{slug}.html` profile per member |
| `search-index.json` | **Generated** search index over stories + people/places/objects/events (also injected into `index.html`) |
| `server.js` | Zero-dependency admin API + local preview server |
| `admin/` | The dashboard: add / edit / publish / delete stories |
| `story/{id}-{slug}.html` | **Generated** — one page per published story |
| `index.html` | The original homepage, updated only inside `<!-- HL:*:START/END -->` markers |

## The editorial workflow

1. Open `/admin/`, click **+ New** (or select a story).
2. Fill in the story and its metadata (people, places, objects, events, themes,
   memory date, publish date, echoes, book part, reading time).
3. Set **Status → Published** and tick **This Week's Story** to feature it.
4. **Save & rebuild** — the homepage's This Week + Archive, the archive count,
   the featured quote, the book progress, and the story's own page all
   regenerate instantly. Publishing a different story automatically demotes the
   previous This Week.

## What "auto-update" means here

`build.js` only ever rewrites the content **between the named markers** in
`index.html`; every other byte of the hand-authored frontend is preserved. The
markup it emits is identical in class and structure to the original, so the
design, animations, theme system and accessibility are untouched.

## The Family Tree

`data/entities.json → family` is the single source of truth. It drives:

- **`family.html`** — a visual, responsive genealogical tree. Each member is a
  clickable card (portrait medallion + name + role); SVG connectors are drawn
  from each couple down to their children and reflow on resize (`ResizeObserver`).
- **`family/{slug}.html`** — one profile page per member, with biography,
  photos (a monogram medallion until a real photo is supplied via `photos[]` —
  no fabricated imagery), relationships (linked both ways), connected stories
  (linking to the published story pages), and a timeline.

Add a person by adding an entry to `family.people` (and, for tree lines, a
`family.unions` record). The next `node build.js` — or any admin save, which
rebuilds everything — regenerates the tree and profiles. No HTML is hand-written.

## Search & Discovery

A global search bar sits at the top of the Archive on the homepage. It searches
**stories, people, places, objects and events** at once — instant while typing,
results grouped by category, fully keyboard-operable (↑/↓ to move, Enter to open,
Esc to close), and every result links to the correct page (story → story page,
person → profile, place/object/event → the story where it appears).

The index is generated by `build.js` from `stories.json` + `entities.json`, then
**injected into `index.html`** so search needs no network request, and also
written to `search-index.json`. Stories carry an optional **Search keywords**
field (editable in the admin) to widen discovery. Every publish/save rebuilds it.

## Knowledge Graph

Every relationship is computed, never hand-maintained. `lib/graph.js` resolves
each story's `people/places/objects/events` strings against every entity's
`name`/`aliases` (unioned with any seed ids), producing a full bidirectional
graph from `stories.json` + `entities.json`:

- **Story pages** show *People, places & things* (linked chips) and *Related
  memories* (other stories sharing entities, ranked by overlap).
- **Every entity has a profile** — people at `family/{slug}.html`, and
  places/objects/events at `place|object|event/{slug}.html` — each listing all
  connected stories and all co-occurring entities ("Also appears with").
- **Automatic backlinks**: an edge added in either file appears on both ends on
  the next build. Search results for places/objects/events link to their new
  profile pages.

Add a reference (or an alias) and rebuild — the graph re-wires itself.

## Hero candle (isolated video cinemagraph)

The homepage centrepiece is a real candle **video loop** — not SVG, CSS, Canvas
or Three.js. It is **isolated with no rectangular box**: the source is a real
candle recorded on a solid **black** background, and the CSS removes that black.

- **Isolation** (`.hero-candle`, styled in `assets/experience.css`):
  `mix-blend-mode: screen` drops the black background and a feathered radial
  `mask` dissolves the video edges — no border, radius, box-shadow or visible
  media frame. A soft, feathered **warm pocket** sits behind the flame in the
  light theme so it reads against warm paper (removed in the dark theme); the
  flame glow spills gently onto the nearby hero.
- **True transparency**: with an **alpha** candle video (transparent bg), set
  `data-source="alpha"` on the `.hero-candle` figure — the blend and the
  light-theme pocket switch off automatically; the candle is genuinely isolated
  on any background.
- `<video autoplay loop muted playsinline preload="metadata">`, WebM + MP4.
- **Graceful fallback**: poster -> static still (`assets/candle-poster.svg`, a
  candle on black that blends identically). Under `prefers-reduced-motion` the
  video is paused on its first frame.
- **Performance**: metadata-only preload; `experience.js` plays it only when
  on-screen and the tab is visible, pausing otherwise.
- **Accessibility / responsive**: video is `aria-hidden` (decorative); the
  Friday signal stays in the caption (`role="status"`); the hero recomposes to
  a centred single column on small screens, candle proportional to the heading.

**Drop in the footage** to go live (candle on black), no code change needed:

```
assets/candle.webm   (VP9/AV1, ~1080x1440 portrait, seamless loop, muted, BLACK bg)
assets/candle.mp4    (H.264 fallback, same loop, BLACK bg)
# or an alpha/transparent video + data-source="alpha" on .hero-candle
```

Until those files exist the page shows the poster still — the same graceful
fallback a visitor gets if their browser blocks video.

## Family Photo System

Archival-quality, fully data-driven. No image path is ever hardcoded in a
template — everything derives from `personId` + `photoId` + generated widths.

**Data layer** — `data/photos.json`, keyed by person id:

```
"harlan": {
  "primary": "<photoId>",
  "items": [ { "id","file","caption","year","location","source","alt",
               "width","height","portrait":[w…],"full":[w…] } ]
}
```
Editorial fields (primary, order, caption, year, location, source, alt) are
preserved across re-processing; only new files are added.

**Pipeline** — `lib/photos.js` (run by `npm run build`, before the site build):
reads archival originals in `photos/{personId}/`, and for every image writes
optimized derivatives to `assets/photos/{personId}/`:

```
{photoId}.portrait.{176,352,528}.webp|jpg   square, face-centred crop (no distortion)
{photoId}.full.{640,1280}.webp|jpg          aspect-preserved (ready for the future gallery)
```
Widths never upscale past the source. Requires `sharp` (an
`optionalDependency`); without it the data layer still works, just no new
derivatives.

**Association** — source folders map to people automatically
(`HARLAN YAFFE→harlan`, `HAL YAFFE→hal`, `Marvin J. Yaffe→marvin`,
`ZANDRA L. YAFFE→zandra`).

**Rendering** — the circular medallion (`portrait()`) emits a responsive
`<picture>` (WebP + JPEG `srcset`, `sizes`, `loading="lazy"`, `decoding="async"`,
descriptive `alt` on the hero, `object-fit:cover` crop). Profiles show **only the
primary portrait** for now; if more exist they show **“More photographs (X)”** —
the slideshow is intentionally not built yet.

**Admin** (`/admin/` → *Photos*): pick a person → upload multiple images (each
optimized on upload), choose the **Primary portrait**, **reorder** the gallery,
edit caption/year/location/source, or delete. Every change rebuilds the site.
API: `GET /api/photos`, `POST /api/photos/:id` (upload), `PUT /api/photos/:id`
(primary + order + metadata), `DELETE /api/photos/:id/:photoId`.

## Experience layer

`assets/experience.css` + `assets/experience.js` are an additive polish layer
loaded by every public page (never the admin). They add craftsmanship only —
no redesign: a realistic layered 3D candle (gradient wax, glowing wick, three
flame layers + breathing halo, pointer-reactive lean), premium typography
(optical sizing, kerning/ligatures, balanced headings, pretty/​hyphenated
reading columns), cinematic cross-document page transitions (View Transitions
API), a physical scroll feel (scroll-driven parallax), ambient breathing light,
and refined hover/motion. **Every motion is gated behind
`prefers-reduced-motion`** and every effect degrades gracefully, so performance
and accessibility are unchanged. Nothing else depends on these files.

## Future entity pages

`data/entities.json` also assigns stable ids and slugs to every place, object
and event. A future `places/`, `objects/`, `events/` generator can reuse the
same pattern in `build.js` without touching the frontend or the data model.
